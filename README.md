# Futbolchi Pro (MVP)

A browser football career game. You create a fictional footballer, pick one training option a week, and watch the matches play out automatically in a 2D replay. Each season ends with a summary, a story and a shareable card. You climb from an academy club up a fictional league pyramid. The UI is in Uzbek; the code is in English.

## Run

```bash
npm install
npm run dev          # starts both: API on :8787 and the game on http://localhost:5173
```

Open the game at **http://localhost:5173**. Port 8787 is the API server only; opening it in a browser redirects to the game. To run the two separately: `npm run dev:server` and `npm run dev:web`.

## Languages

The game ships in **Uzbek (default), English and Russian**. The UZ / EN / RU switch sits in the top-right corner of the entrance screens only — loading, name and main menu — and changes the language instantly (the choice is remembered). It is hidden once the game starts so it does not distract; to change language, go back to the main menu (click the logo).

- All UI text lives in `apps/web/src/i18n/uz.ts`, `en.ts` and `ru.ts`. **Never hard-code text in a component** — add the key to all three files. The `Messages` type breaks the build if a language is missing a key, and `apps/web/test/i18n.test.ts` fails on empty or untranslated text.
- The season story is generated by the engine in all three languages (`seasonStory(facts, lang)`), including Russian plurals and cases.
- Long Russian text must still fit the PC layout: check new screens at 1366×657 in all three languages.

## New player flow

1. **Loading** — a rolling counter shows how many players have registered (`GET /api/stats`, a real count).
2. **Main menu** — the player enters a name; the price (5 000 so'm) appears next to *Davom etish*.
3. **Payment** — the player transfers to the card shown, uploads a receipt image ("chek") and waits. The page polls and continues by itself once an admin approves.
4. **Persona** — a 64×96 shaded pixel avatar that updates live. Appearance is split into tabs: face (head shape, skin, eyes, brows, nose, facial hair), hair (11 styles with portrait previews, 8 colours), body (height, weight, strong foot) and kit (boots, sleeves, accessory, goal celebration). A random button and a celebration preview sit on the avatar. Then position and bonus points. Appearance is cosmetic only; older saves get defaults for new options (`normalizeAppearance`). Kits are plain colours: no real clubs, sponsors or logos.
5. **Game.**

## Server settings (environment variables)

| Variable | Purpose | Dev default |
|---|---|---|
| `PAYMENT_CARD_NUMBER`, `PAYMENT_CARD_HOLDER` | Card shown to players on the payment page | placeholder `0000 0000 0000 0000` |
| `PERSONA_PRICE_MINOR` | Price in tiyin | `500000` (5 000 so'm) |
| `ADMIN_NICK` | Secret nickname that opens the admin login from the name screen | `admin1121` (off in production if unset) |
| `ADMIN_TOKEN` | Admin panel token | `dev-admin-token` (admin is disabled in production if unset) |
| `PAYMENT_EVENT_SECRET` | Signs admin payment decisions | dev value (required in production) |
| `DATA_DIR` | Where `db.json` and receipt images are stored | `apps/server/data` |

Put these in `apps/server/.env` (copy `apps/server/.env.example`; git-ignored). It is read on start in any shell — PowerShell, cmd or bash — and the dev server restarts when it changes. Variables set in the shell win; an empty value means "use the default".


## Admin panel

Three hidden ways in (normal players never see them):

- type the secret nickname (`ADMIN_NICK`) on the name screen — it is checked by the server, never registered as a name, and only opens the login form;
- press **Ctrl+Shift+A** anywhere;
- open `http://localhost:5173/#/admin`.

The admin token is still required once. After that this browser remembers it (`Chiqish` forgets it), and the payment page shows an extra **Admin: to'lovsiz o'tish** button that grants a free slot (a 0 so'm receipt) and goes straight to persona creation. The nickname alone never grants access: it is easy to guess or leak, and anyone typing it would get in for free.

The panel has a stats row (players, receipts waiting, approved, revenue) and three tabs:

- **To'lovlar** — receipts waiting for review first, with the image shown right away (click to enlarge). Approve, or reject with a reason typed inline; the player sees the reason and can send a new receipt on the same page. The list refreshes every 10 s.
- **To'lovsiz kirish** — a free persona slot for this browser.
- **Highlightlar** — mark match events as highlights.

## Layout

| Path | What |
|---|---|
| `packages/engine` | Pure, deterministic simulation (no DOM, no I/O, no `Math.random`). Persona, training, match, league, season, story. |
| `apps/web` | Vite + React SPA. Game state lives in `localStorage` as plain JSON. Includes the canvas replay and share card. |
| `apps/server` | Fastify. `PaymentProvider` interface with a manual provider (receipt upload + admin approval) and a mock (tests), idempotent payment events, receipts, save sync, admin. JSON-file store and receipt images in `apps/server/data/` (git-ignored). |
| `BALANCE.md` | Every formula and tunable number. |

## Stack rationale

- **TypeScript everywhere.** One data model is shared by the engine, the UI and the server.
- **The engine is a plain TS package.** It is testable on its own, and later the server can re-simulate a match to verify a result.
- **Vite + React.** Widely used and quick to build with. The replay is a plain `<canvas>`, so no game engine is needed.
- **Fastify + JSON store.** It gives a real webhook endpoint now. The store can be swapped for Postgres or SQLite later.
